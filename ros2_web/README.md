# 机器人中控台 (Robot Control Console)

## 项目简介

这是一个基于 Web 的机器人中控台，用于实时监控和控制 ROS 2 机器人。该项目集成了地图展示、摇杆控制、状态监测以及建图管理等功能。

项目演示视频：[Bilibili](https://www.bilibili.com/video/BV1wx326wEw6/?vd_source=339f0240733dcda285627ff53cbd145f)

## 核心功能

* 实时 SLAM 栅格地图显示。
* 机器人摇杆与键盘远程控制：W/S 前后、Q/E 横移、A/D 转向，并可在控制卡片中设置线速度和角速度。
* 机械臂控制工具栏：按实物测量限制 1–4 号舵机角度；5 号夹爪限制为 120–180°，120° 完全张开、180° 闭合。各通道独立记住本页上次成功发送的目标角度。支持一键回正（90°/0°/180°/180°/180°，通道间隔 1.2 秒）和末端 X/Y/Z/俯仰角目标设置。
* 摄像头卡片增加“颜色跟随”：选择红、蓝、绿、黄、橙色方块，用红框标注目标，并可启动机械臂小步居中跟随。颜色分割在 Windows 浏览器处理，默认最多 320×240、8 帧/秒，主控无需运行额外推理或转码进程。
* 里程计数据实时监测。
* 自动发现并播放 MediaMTX WebRTC 通道，同时支持 HTTP/MJPEG 摄像头地址。
* Foxglove Bridge 仅开放中控台所需话题和客户端发布能力，以降低板端 CPU 占用。
* 网页订阅 12 Hz 的 `/web/tf` 和 10 Hz 的 `/web/odom`；机器人控制与导航仍使用原始 `/tf` 与 `/odom`。开机服务使用惰性订阅，无网页客户端时不处理上游数据。
* 可视化建图控制（开始/停止建图）。
* 地图保存功能，支持在网页端输入地图名称。
* 视图自动重置功能，在开始建图/导航时自动对齐视野。
* 页面自动连接 Foxglove WebSocket（默认 `ws://<页面主机>:8765`）。
* 连接成功会显示“已连接”，连接失败会显示错误信息。

## 环境要求

### 网页单舵机角度限制

| 通道 | 可发送角度 |
| --- | --- |
| 1 | 20–180° |
| 2 | 0–170° |
| 3 | 0–180° |
| 4 | 40–180° |
| 5（夹爪） | 120–180°，120° 完全张开、180° 闭合；低于 120° 拒绝发布 |

切换通道后，输入框、滑块及可视化范围随通道更新，并恢复该通道最近一次成功发送的目标角度。例如通道 1 发送 50° 后，切到其他通道再回来，仍显示 50°。仅拖动但未发送的角度不会覆盖记录；切换本身不会发送命令。手动输入越界或非数字会被拒绝，实际发布入口也使用同一校验。一键回正先校验全部通道，再依次发布，并按实际发送结果逐通道更新记录。

记录保存在当前页面运行期间，断线重连不清除，刷新网页后重新开始。尚无记录时显示待发送参考值，通道 1–4 为 90°、夹爪为 120°；这些值不是测量到的当前位置。记录代表浏览器成功发送的目标角度，不证明硬件已执行完成，也不会跟踪其他控制器或末端位姿命令造成的关节运动。

限制定义位于 `src/config/servoLimits.js`。这套限制针对本网页的单舵机及回正命令；末端位姿服务中的逆解，以及其他 ROS 发布者的关节限位需要由控制器另行校验。

可运行 `npm test` 检查边界、夹爪连续角度、发布拦截及发送记录，`npm run build` 检查网页构建。

### 颜色识别与机械臂跟随

本车摄像头位于夹爪上方，跟随固定使用用户实测的 1 号左右通道和 4 号上下通道。通道 1 角度增大向左转，通道 4 角度增大向下走。目标偏右时通道 1 减小 10°，偏左时增大 10°；目标偏下时通道 4 增大 10°，偏上时减小 10°。

1. 在 Windows 打开控制台，确认 WebRTC 视频正常显示。
2. 手动将跟随使用的两个关节调整到适合观察方块的姿态，并发送角度，建立本页的目标角度记录。
3. 点击摄像头卡片上的“颜色跟随”，选择方块颜色，确认红框只框住所需目标。
4. 点击“开始跟随”，程序按已确认的实物方向直接纠偏，一次只发一个关节，每步固定 10°。尚无目标时也可开启跟随，保持等待而不发运动命令。目标出现并确认后自动继续。同向且偏差较大时，最早 0.8 秒更新同一个关节的目标，利用原 ESP 约 1 秒的插值连续过渡，减少停顿；换关节、换向和近中心时等待至少 1.2 秒，让动作与画面反馈稳定。实际间隔按 8 FPS 采样调度，约为 0.875/1.25 秒。接近限位时截断到边界，最后一步可以小于 10°，不会越界。
5. 之后缓慢移动方块，目标尽量保持在中心十字附近。点击“停止跟随”停止运动，颜色识别可继续显示红框。

目标位置使用 160 ms 时间常数的轻量低通滤波，减少画面抖动；相近的水平/垂直偏差优先保持当前关节，避免频繁换轴。同向连续发令只用于偏差仍超过画面轴向 12% 的情况，且没有偏差增大或无响应迹象。

固定 10° 可能跨过画面中心。程序会保留较近的一侧，必要时退回一次，然后暂停该方向，避免在两个角度间来回摆动；目标再次移动后继续调整。近中心、退回或换轴不使用快速连续发令。精确中心受固定步长限制。

没有目标时保留颜色识别和已开启的跟随状态，暂停发令、清除旧目标反馈；目标重现后重新确认，自动继续，不需要再次点击开始。目标重现过快时先等待上一动作完成。手动停止后不会因目标重现而自动恢复。

摄像头画面丢失、缓冲中断、超过 600 ms 没有新帧或像素不可读取时关闭识别和跟随，显示停止原因；视频恢复后需手动重新开启。ROS 连接断开、关节限位、连续动作无视角响应、偏差持续增大或页面隐藏时停止跟随，不自动恢复。跟随时锁定手动机械臂与末端位姿控制；手动控制忙碌或导航运行时不能启动，底盘移动或导航目标操作会停止跟随。跟随不发送夹爪动作，所有关节目标经过共同限位校验并更新本页发送记录。

视频改为直接使用 MediaMTX 的 WebRTC reader 显示到 `<video>`，沿用原通道和视频数据，便于浏览器读取像素和叠加红框。HTTP 图像在支持跨域时可用于识别，但自动跟随要求可监测新帧的 WebRTC。纯色分割和紧凑轮廓筛选不测量真实 2.5 cm 尺寸；同色背景、光照与遮挡会影响结果，需要在实际环境验证。

### 运行环境

* Ubuntu 22.04 (WSL 兼容)
* ROS 2 Humble
* Node.js (建议版本 v18+)
* foxglove_bridge

## 快速启动

在项目根目录下执行以下脚本，即可同时启动后端服务和前端界面：

```bash
bash start_console.sh
```

启动成功后，在浏览器访问：`http://localhost:5173`

## 部署配置 (重要)

当您将项目部署到自己的电脑或机器人上时，ROS 2 启动命令、话题名、地图路径、摄像头地址等运行配置均以项目根目录下的 `ros_config.json` 为准。

如果 README 中的说明与 `ros_config.json` 当前内容不一致，请以 `ros_config.json` 为准。

### 1. 修改 `ros_config.json`

该文件位于项目根目录，控制着所有 ROS 2 指令的触发和路径：

* **`tasks.startup`**: 后台启动任务，当前用于启动 Foxglove Bridge。
* **`tasks.mapping`**: 建图启动命令，当前为 `ros2 launch slam_gmapping slam_gmapping.launch.py`。
* **`tasks.navigation`**: 导航启动命令，当前为 `ros2 launch xuegecar_navigation2 lite_navigation.launch.py`，使用单进程轻量定位、A* 与全向路径跟踪。
* **`save_map.save_dir`**: 地图保存目录，当前为 `/root/chuyun_ws/src/xuegecar_navigation2/maps`。
* **`maps_dir`**: 历史地图读取目录，当前为 `/root/chuyun_ws/src/xuegecar_navigation2/maps`。
* **`camera.stream_url`**: 摄像头视频流地址，当前为 `http://192.168.31.194:8081/`。
* **`topics`**: 前端订阅和发布的 ROS 2 话题名。如果机器人的话题名不同，请直接修改这里。

## 配置说明

项目核心逻辑由 `ros_config.json` 驱动，你可以直接在该文件中修改 ROS 2 指令：

* `startup`: 配置后台自动运行的任务（如 Foxglove Bridge 的高带宽模式设置）。
* `mapping`: 配置建图算法及其参数。
* `navigation`: 配置导航启动命令及参数。
* `save_map`: 配置地图保存命令及保存路径。
* `camera`: 配置摄像头视频流地址。
* `topics`: 配置前端使用的话题名（不同机器人可直接改这里）。

`topics` 典型字段：

* `cmd_vel`
* `map`
* `costmap`
* `scan`
* `tf`
* `odom`
* `plan`
* `goal_pose`
* `initial_pose`
* `navigate_feedback`
* `imu`
